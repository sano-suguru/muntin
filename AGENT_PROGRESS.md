## M3-008 result (JSON codec decision; no product behavior; not merged)
- Decision: `Json[T]` (Muntin-owned; `FromBody` where `T: FromJson`, `ToResponse` where `T: ToJson`; `take(deinit self)`) over application traits `FromJson.from_json(JsonValue) raises -> Self` and `ToJson.write_json(mut JsonWriter) raises`, with a Muntin-owned strict RFC 8259 codec: `JsonValue` is a read-only position in a flat tape held in M3-004's `_Shared` (recursive structs do not compile; `ArcPointer` would let a copy clear the tape), `JsonWriter` raises on misuse and NaN/infinity. `def create_user(body: Json[CreateUser]) -> Json[User]` registers on the existing overloads (stateful included): no overload added, no diagnostic changed.
- Content-Type: a JSON response is 200 with exactly `Content-Type: application/json`; `String`/`Response.text` unchanged (no field); override = convert, then `set` (wins). A JSON request needs exactly one `Content-Type` with media type `application/json` (case-insensitive, parameters such as `charset=utf-8` ignored), else 415 (CSRF: browsers send `text/plain`/form/no type without preflight; strict is reversible). Order: 404, query 400, route value 400, 415, JSON 400, handler. Errors: malformed JSON or a `from_json` raise is 400 before the handler; handler raises unchanged; a serialization failure is the fixed 500 without the handler's `ToErrorResponse`. M2 stays closed (415 only for the new Muntin-owned body).
- Facts: Mojo 1.1.0 std has no JSON; the lock's only JSON package ships inside Flare's package (flare env only, `__extension`, native simdjson wrapper). `atof` is lenient and rejects long literals (codec validates grammar; long literals are a pinned 400 gap). Flare passes request/response `Content-Type` unchanged, its `HttpClient.post(url, String)` adds `application/json` itself, and invalid UTF-8 arrives as U+FFFD.
- Rejected: B (refining trait defaulting the parent's `from_body`: compiles, DX-exact, undocumented; `tests/json_known_gaps`), C (helper only: no request side, serialization failure becomes a handler error), 4a (11th `post` overload: `ambiguous call to 'post'`), 4b (relaxed bounds: 16 bounds/asserts, function-type `rebind` in `App`, 6 pinned diagnostics change), 5 (no codec), the Flare-bundled package, derived reflection codecs (no constructor, `Defaultable` dummies, `List[struct]` needs `__extension`, late diagnostics; deferred).

## M3-004 result (state storage decision; no product behavior; merged, PR #27)
- Why: the PR #26 review of M3-003 showed that with an `ArcPointer` field, code holding a second `State` handle frees memory a `state[]` reference points into, with public std API alone (`ArcPointer.__getitem__` is mutable through any handle; no private fields on 1.1.0). This holds for M3-001's `ArcPointer[S]` (`b._shared[].names.clear()`) and for PR #26's `ArcPointer[OwnedPointer[S]]` (`b._shared[] = OwnedPointer(...)`, the review's case). Not an M2 reopen; it reverses M3-001's internal "no unsafe code" choice.
- Guarantee (restated after the gate's review): Muntin introduces no Muntin-specific safe-code path that lets one `State` alias replace, mutate, swap or prematurely destroy the payload another alias observes. Toolchain-wide primitives that break the same property for std types and existing Muntin storage are outside it and pinned in `tests/toolchain_soundness_gaps` (must build): `rebind` origin laundering (even through public `state[]`, and on a std `List`), forged `alloc` headers swapped in by field name (also crashes `_Erased` on main), `memmove`, stdlib-private fields. The literal "no name or safe pointer API reaches the payload" bar fails for every type on 1.1.0. M2-004's "what Muntin controls is now closed" is corrected to "ordinary safe-code paths Muntin exposes are closed; Mojo-wide escape hatches are outside". Not an M2 reopen.
- Decision: a sealed `_Shared[S]` in `_handler_storage.mojo` (one `ThinAllocation` field; header = atomic count with `ArcPointer`'s orderings + `OwnedPointer[S]`; `owned(self)` immutable). `State`'s public API unchanged. On ordinary paths through a second handle, replace/mutate/swap is a compile error; reassignment and move invalidate `state[]` references; only the toolchain-wide primitives reach the payload, as they reach `_Erased` and std types. Cost: two allocations per `State`, none per request. Guard: `_Shared` may be imported; PR #26's `OwnedPointer` exemption goes. Details: `docs/ARCHITECTURE.md` "State storage decision (M3-004)".

## M2-003 result (decision only; production unchanged)
- Decision: production `App` moves from the closed `Variant` to a private typed box with pointer erasure, in a separate behavior-preserving PR before any new handler shape. Details, matrix, unsafe invariants, sources and thresholds: `docs/ARCHITECTURE.md` "Handler storage decision (M2)".

## Decisions in force
- Muntin owns `App`/`Request`/`Response`; backends call `App.handle`. No backend trait until a second backend exists (A7).
- Handlers are thin function values (`def() -> String` is a trait in Mojo 1.1.0; repro in `docs/DX.md`) stored in a private move-only typed box since M2-004 (`Variant` in M2-001 to M2-003). Users still write plain `def hello() -> String` / `def get_user(id: Int) -> String`. Unsafe code stays in `src/muntin/_handler_storage.mojo` (`check_unsafe.sh`).
- `TestClient[origin: Origin[mut=False]]` borrows the app via `Pointer`, so `TestClient(app)` matches DX without copying.
- Request/Response own `String` data; no backend buffer lifetimes in public types.
- `check.sh` asserts the `Mojo 1.1.0` prefix; upgrading Mojo is a deliberate change that must update the script and docs.

## Remaining limitations
- No `app.run()`: the only listening socket is the M1-003 test fixture. Whether `app.run()` belongs to Muntin (DX.md lists it as a target) is undecided; SPEC M1 does not require it. The fork + SIGKILL fixture is a test harness, not a template for `app.run()`.
- Handler shapes: GET `def()` or `def(Int)`, POST `def(B: FromBody)` or `def(Int, B: FromBody)`, each `-> String`-compatible or `-> R: ToResponse`, raising or not. A handler error is the fixed 500 unless its declared `raises T` type conforms to `ToErrorResponse` (M2-013); no `Error` mapping, no application-level or per-route mapper, no fallible error conversion, and a dropped error is not logged (no logging hook). No fallible `to_response`; raw handlers (M2-015) return `Response` only and their routes are static (no placeholders); no multi-parameter shapes other than `(Int, B)`, no `var` route values, no `String`/builtin bodies, no JSON, no optional/multiple bodies, no POST without a body, no other methods, no multiple/non-`Int` path or query parameters, no path+query handler, no optional/default query values.
- Route literals are validated at compile time (shape, arity) but stored and split as runtime `String`s per request.
- `Request` and `Response` have headers since M3-005; there is still no default `Content-Type` and no typed header extraction.
- Route lookup is a linear scan; overlapping or duplicate registrations silently use the first match; no percent-decoding of path or query; `#` is not special; query keys are positional, not checked against handler parameter names. Query keys must be visible ASCII (compile time), but static path segments are not checked: `/hello world` compiles and matches through TestClient but never over Flare, which rejects target bytes outside `!`..`~` (pre-existing since M2-001).
- `muntin.testing` is imported by `main.mojo` only because `app.run()` does not exist; it is not the canonical example.

## Risks for later milestones
- Handler storage: Mojo 1.1.0 has no private fields. `_Erased` exposes only a move-only handle, but the stdlib's private `ThinAllocation._ptr` (and the deprecated `memmove`) stays usable from application code, as for every owning stdlib type and for the previous Variant. Drop pairing is kept by construction and the count oracle. A future need to copy an `App` would need clone support back, with its own oracle. Application body types need no `downcast`: M2-005 checks them with documented `conforms_to` refinement. Closures and captured state remain unsupported.
- Responses carry no Content-Type on the wire (observed in M1-003); Muntin `Response` had no headers (added in M3-005, still no default Content-Type).
- Absolute-form request targets (`http://host/path`) are not handled: the whole target becomes `path` and 404s. Flare's client sends origin-form; a proxy-facing server could receive absolute-form.
- CI: `ubuntu-latest` moves to Ubuntu 26 from 2026-10-19. Current green evidence is ubuntu24; if the flare job breaks after that date, compare `ImageOS`/`ImageVersion` in the `runner image` step before blaming Muntin or Flare.
- The first loopback test (`/hello`, unchanged since M1-003) is slow on a cold start: ~26 s locally once, 11–21 s on macOS CI for M2-001, 64 s on macOS CI for M2-002 (it passed; the child `alarm` is 30 s, so the time is not all inside the serving window). If it flakes, look at this before blaming routing.
- The localhost round trip relies on `fork(2)` in a Mojo process (as Flare's own tests do); Windows is out of scope. Its child exits only via SIGKILL or the 30 s alarm, since v0.11.0's `close()`/`drain()` need a second thread.
- The flare CI job rebuilds Flare's C/C++ FFI wrappers from source on every run (no cache, ~1 min).
- M1: v0.11.0's old server spellings (`bind_many`, `serve_tls`, ...) are shims removed in v0.12; use `HttpServer.bind`/`serve`. Flare's `Request` is `Movable` and holds `List[UInt8]` bodies, so the adapter copies into Muntin's `String`-owning types.
- M1: Flare HTTP/3 is unavailable from the conda build (no rustls cdylib); irrelevant unless Muntin needs h3.
