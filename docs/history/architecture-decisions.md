# Architecture decision records

Why Muntin's architecture is as it is. Each record is a file in [`decisions/`](decisions/), listed [below](#records) in the order of the single file they were written in, which is nearly the order written; an "above", "below" or "the next section" that points to another record means earlier or later in this list; one that points within a record keeps its usual meaning, and "this section" means that record. A record's shape, size and next action: `docs/DEVELOPMENT.md` section 2. A slice is the production item's contract, and implementing it as written adds no record. An amendment record is for a slice that cannot be implemented as written: it states the delta to the slice, why, the invariant or compatibility boundary it affects, and the revised slice, before the change merges. A change that raises a new design question is a new decision, not an amendment. Each new record names its pull request, where the evidence (test counts, mutations, review findings, CI runs) lives. `docs/ARCHITECTURE.md` is the current state; where a later record changed an earlier one, the later record and `docs/ARCHITECTURE.md` win. Its revisit index maps each pinned fixture to the record it protects.

Each record opens with its state, the later records that changed part of it, and where the behavior it decided is described now. A record is current when its choice holds, even if later records built on it or changed a part; superseded when a later record replaced its choice, or when it makes no choice of its own and only describes the code at the time (the M0 layout), and later records changed that code; withdrawn when its choice was reversed and nothing replaced it. The state is judged by the record's main choice, so a current record can still state details that are no longer true: its "Changed in part" list names them, and the current documents win.

Earlier records include production records written before that rule; they stay as history. A record's status line and "Next production slice" describe the plan when it was written. Older records cite files that have since been removed (`docs/history/spec-items.md`, `docs/history/progress-log.md`, `feature_list.json`, `.claude/rules/`, `AGENT_PROGRESS.md`, item results under `docs/SPEC.md`, M2 contract amendment paragraphs in `docs/SPEC.md`), and fixtures that later items retired; git history has them. `docs/DX.md` and the old `docs/ARCHITECTURE.md` headings they cite are mapped [below](#documents-older-records-cite).
