# Guarded routes and request context decision (M3-080)

> **Draft.** Only the question is written; the choice follows the evidence and the owner's decision on its pull request.

Status: **decision** (M3-080, its pull request; issue [#151](https://github.com/sano-suguru/muntin/issues/151)). The spikes, probes, sanitizer runs and review are in the pull request.

**Question and what settles it.** The notes application (#167) calls `authenticate(svc, headers)` in every handler: middleware cannot read the token table built at start-up ([M3-034](m3-034-middleware-decision.md)), cannot hand a handler the user ([M3-065](m3-065-request-context-storage-decision.md) withdrew open storage), applies to every route or none, and runs before Muntin's 400s only when it is global. Which shape lets an application write that check once, with start-up values, for a group of routes, before their route values and body are converted, and hand each handler the user as a typed value whose type the check and the handler share statically? The candidates are those of [the deferral](../deferrals.md#request-context-over-a-closed-type-m3-065): a typed group of routes with its own check, moved into the `App`; `App[Ctx]`; and the check passed at each registration, as `State` is. Settled by a spike of each candidate under `tests/` (`src/muntin` unchanged) that rewrites the notes application so that adding a protected route needs no authentication call; the deferral's soundness conditions shown along the whole path under AddressSanitizer, and a context or group type that borrows a local refused at compile time; and, for the candidate chosen, a scratch copy of production passing `check.sh`, `test.sh` and `check_flare.sh` unchanged, with its overload count against [M3-052](m3-052-registration-complexity-budget-decision.md)'s budget and a fresh-context review. If no candidate meets the soundness conditions, the item records a deferral instead.
