# State borrowing decision (M3-074)

> **Current.** Now described in [state reference, "Rules"](../../reference/state.md#rules) and [ARCHITECTURE, "Storage and ownership"](../../ARCHITECTURE.md#storage-and-ownership).
> Its pointers into documents that were split or renamed since (`docs/DX.md`, old `docs/ARCHITECTURE.md` headings) are mapped in [the list of records](../architecture-decisions.md#documents-older-records-cite).

Status: **decision and production** (M3-074, pull request #135; issue [#122](https://github.com/sano-suguru/muntin/issues/122)). The probes and the base builds are in the pull request.

**Question and what settles it.** A route erases its `State[S]` (`_Bound[H, S]` in `_Erased`), and the `App`'s type does not carry the origins in `S`, so a state whose type borrows a local registered, the checker ended the local at its last use, and a request read freed memory, in safe code ([M3-065](m3-065-request-context-storage-decision.md) found it; issue #122). How can registration refuse such an `S` without refusing a state that owns its data, including one passed through a helper generic over `S` ([M3-015](m3-015-registration-structure-amendment-generic-forwarding.md))? #122's criteria: each of its three reproductions refused at compile time by a must-not-build fixture, or served under AddressSanitizer, and no `State` holding owned data stops compiling; probes of each candidate with Mojo 1.1.0. No candidate meets both (below), so this decision narrows the second criterion to the compatibility bullet below; the owner approved that narrowing as a requirement change on pull request #135 (2026-10-16).

**Choice: `State.__init__` refuses, at compile time, an `S` whose reflected name shows `{}`.** A `comptime assert` on `reflect[S].name()`, with Muntin's message naming the type. Mojo 1.1.0 prints every origin as `{}` (local, argument, static, `AnyOrigin`), and a parameter pack (`Tuple`, `Variant`, any variadic struct) as `<unprintable>, {}` whatever its elements, so a pack is refused too.
- What it closes: a value borrows a local only through that local's origin in its type; no module-level declaration (a field, a `comptime` member, a trait's associated type) can name it, and a struct cannot be declared inside a function, so it reaches a field only as a parameter of `S` or of a type in its name, where it prints or hides in a pack; a closure that captures by reference prints its origin too. A function-valued parameter prints as `<unprintable>` alone and passes: it can bind a local's origin out of the name, but it is a compile-time value with no address. A closure over a local is a runtime value Mojo refuses as a parameter (`state_function_parameter_captures_*`). The pointer such a function would read, or a field typed by its result, needs a type Mojo makes concrete: an open result origin or a call through an open-typed parameter does not compile (`state_function_parameter_{open_result,result_type}`), so its origin is a struct parameter, which prints (`state_origin_in_function_{parameter,result}_type`; the second reads freed memory on the base), or `AnyOrigin`; `test_function_parameter_hides_no_address` serves one after its local is gone.
- What it does not: `AnyOrigin` can stay out of the name, through a trait's associated type (a field typed `Self.T.Ptr`) or a closure that captures such a pointer by value (which no thin handler can call on 1.1.0), so a pointer to a local built with `ImmutAnyOrigin` still registers (`tests/state_known_gaps/state_any_origin_associated_type.mojo`, heap-use-after-free under `scripts/run_origin_gaps.sh`). It is the toolchain-wide `AnyOrigin` hole (`tests/registration_known_gaps/safe_dangling_any_origin_slice.mojo`), which #122 left out; Muntin claims nothing for values built with `AnyOrigin`. Every registration path takes a `State` from this initializer, so one check covers them all.
- It reads an undocumented format, which [M3-065](m3-065-request-context-storage-decision.md) rejected as a type identity. Here it is a filter whose failure is visible: if Mojo stops printing an origin as `{}`, the `tests/state_fail/state_origin_*` fixtures build and `check.sh` fails, so the gap cannot reopen silently.
- Generic forwarding keeps working: the assert runs on the instantiated type, so a helper generic over `S` needs no clause.
- **Compatibility: owned states that stop compiling.** The name cannot tell a static origin from a local one, nor an owned pack from one holding a borrow (`Tuple[Int, String]` and `Tuple[View[o]]` both print `Tuple[<unprintable>, {}]`; the pack field is an MLIR type reflection does not open; a linkage name drops origins). On Mojo 1.1.0, `{}` appears in a name for exactly these, each refused anywhere in `S`'s name, a type argument's included, although the value may own its data: an origin parameter of any kind (local, argument, static as in `StaticString` or `Optional[StaticString]`, `AnyOrigin`, mutable or not, inferred or explicit); a parameter pack (`Tuple(1, String("a"))`, `Variant[Int, String]`, `List[Tuple[Int, String]]`, any struct with variadic type parameters); a struct value with no fields as a parameter. The migration is a field of the application's own state struct, `struct Pair: var value: Tuple[Int, String]` registered as `State(Pair(Tuple(1, String("a"))))` (`test_owned_values_in_a_wrapper_register`, with a `Variant` twin; `Label` holds a `StaticString`). No existing registration or test in this repository is refused.

**Rejected.**
- A `where` clause on the overloads: the prover evaluates no non-builtin function, so a predicate function refuses every `S`, owned ones included; and no builtin expression of `S` tells an origin apart (`S == S` holds for a local's origin, and generic `==` ignores origin identity).
- Admitting packs or static origins: indistinguishable from borrowing ones, as above, so admitting them reopens #122.
- The `App` carrying the origins (`App[o]`, or a typestate `App` per registration): every function taking an `App` changes, and nothing found relates an `App` parameter to the origins inside `S`.
- State built by a factory with no arguments (`State[make]()`): it cannot borrow a caller's local, but a state could no longer be built from runtime configuration.
- Walking `reflect[S].field_types()` down to pointers: a field type shows its origins only through the same name, packs stay closed, and owned containers hold pointers too.
- Keeping the gap documented: a memory-safety defect in shipped code.

**Revisit when:**
- a `tests/state_fail/state_origin_*` fixture builds: the name stopped showing an origin; find another check before the Mojo change merges;
- Mojo gains an origin bound generic code can state (an outlives or `'static` constraint), documents a parameter reflection, or opens a pack's element types: replace the name check, and admit the owned packs and static origins it refuses (`state_pack_tuple.mojo`, `state_origin_static.mojo`);
- an application needs a pack or a static origin as its whole state type: weigh admitting it;
- another value is erased (M3-057's stream source, a request context group): it applies this rule;
- `tests/state_known_gaps/state_any_origin_associated_type.mojo` stops building or reporting: the `AnyOrigin` hole closed or moved; re-read the bullets above.
