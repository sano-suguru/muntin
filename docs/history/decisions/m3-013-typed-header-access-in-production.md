# Typed header access in production (M3-013)

> **Current.** Now described in [bodies reference, "Header fields with a body (`WithHeaders[B]`)"](../../reference/bodies.md#header-fields-with-a-body-withheadersb) and [routing reference, "Order of checks"](../../reference/routing.md#order-of-checks).
> Changed in part since:
> - [M3-015 production](m3-015-registration-on-generic-arity-slots-in-production.md): the eight body overloads' flag/assert edits and the four body adapters were replaced by the arity overloads and adapters.
> - [M3-030](m3-030-method-not-allowed-decision.md): the order's first step is 404, or 405 with Allow.
> - [M3-042](m3-042-typed-binary-request-bodies-with-header-fields-decision.md): `WithHeaders[B: FromBody]` became `WithHeaders[B: _FromBodyOrBytes]`.
> - [M3-053](m3-053-route-conflict-decision.md): "first registration wins in both orders" for duplicate routes became a registration abort.
> Its pointers into documents that were split or renamed since (`docs/DX.md`, old `docs/ARCHITECTURE.md` headings) are mapped in [the list of records](../architecture-decisions.md#documents-older-records-cite).

Status: **production**, the M3-012 slice. The decision, rejected candidates, invariants, the accepted cost and the revisit conditions are "Typed header access decision (M3-012)" above; this section records what production does and how it differs from the slice as written.

- `src/muntin/headers_body.mojo` (new): public `WithHeaders[B: FromBody](Deinitable, Movable, _HeaderCarrier, _JsonBody where conforms_to(B, _JsonBody))` with `headers: Headers`, `body: B`, `__init__(out self, var body: B, var headers: Headers)` and `take_body(deinit self) -> B`; the private trait `_HeaderCarrier` with `_from_parts(body: String, var headers: Headers) raises -> Self` (`B.from_body`, a raise propagating). It imports `FromBody`, `Headers` and `_JsonBody` only. `muntin` exports `WithHeaders`.
- `src/muntin/app.mojo`: `_Route.headers: Bool` (default `False`). The eight body overloads pass `headers=conforms_to(B, _HeaderCarrier)`, and their last assert is `conforms_to(B, FromBody) or conforms_to(B, _HeaderCarrier)` with its message unchanged; no other guard changes. `App.handle` appends each request field's name and value for a carrier route only, after the body and the JSON verdict. The four body adapters assert `FromBody` or the carrier, and refine `B: FromBody` in the non-carrier branch before `B.from_body`. For a carrier they rebuild the fields (`_carrier_fields`, through `Headers.add`; a raise is `_internal_error()`), then build it with `B._from_parts` (a raise is `_bad_request()`). Differences from the slice as written:
  - the JSON steps are one helper, `_json_status[B]`, shared by the four adapters, with `_json_answer` for its 415/413. Non-carrier JSON bodies keep the exact arity (the verdict `"1"` and nothing after it); a carrier requires the verdict at its fixed index and an even count after it. The module comment, `App.handle`'s docstring, `_call_body`'s docstring and the first body overload's docstring describe the carrier.
- Unchanged: every overload signature, message and count (`get` and `post` keep ten each); `_Erased`, `_Call`, `_Bound`, `_handler_storage.mojo`, `check_unsafe.sh` and the unsafe surface; `State`; `http.mojo` (`Headers`, `Request`, `Response`); `body.mojo`; `json.mojo`; `state.mojo`; `testing.mojo`; `adapters/flare/muntin_flare.mojo`. `App` stays non-generic.
- Accepted cost, as decided: `WithHeaders` is a body-slot type but not a `FromBody`, so `FromBody` no longer names every type a `post` body slot accepts, and generic code bounded by `B: FromBody` does not accept the carrier. Building one by hand takes an explicit `Headers`.
- Behavior: on a carrier route the handler sees every field in order, with its casing, repeated names and empty values; Muntin chooses no status for the fields `input.headers` exposes and gives them no meaning. Two existing checks still answer before the handler: a `Json[T]` body's `Content-Type` verdict (415), and the rebuild of a field an in-memory `Headers` holds invalidly (the fixed 500). Order: 404 → query value 400 (`App.handle`) → route value 400 → for a `Json[T]` body 415 then 413 → field rebuild (the fixed 500, reachable only through the M3-002 `_fields` gap) → `from_body` 400 → handler → result conversion. Routes without a carrier receive the same arguments as before, and raw routes are unchanged.
- Diagnostics: the 262 must-fail fixtures common to `main` and the slice (`main`'s 267 less the five deleted carrier fixtures), built against each `src` with source paths and line numbers normalized: 251 identical (four of them differ before normalization only in the `muntin/__init__.mojo` import line the new export shifts), and 11 differ only in the source line the compiler echoes under the relaxed assert. They are the 11 the decision measured; their errors, messages, notes and carets are identical and every expected text matches.
- Evidence:
  - `tests/test_with_headers.mojo` (14), through `App.handle` and `TestClient` (`headers=`): one carrier handler on each of the eight body overloads, each sent fields, with fields in order, casing and repeats and the two transports equal; absent and empty fields; a handler-chosen 401 for a missing credential on the six JSON carrier routes; `from_body` 400 with fields present; the route value first (path and query); `State` with the reference count read inside handlers equal to the count between requests; `take_body` with a move-only body; `WithHeaders[Json[T]]` on all four body shapes (path and query route values) with the full order, each step measured with later failures present, including a field named `1` and two `Content-Type` fields; plain and JSON routes without a carrier, and raw `GET`, raw `POST` and stateful raw routes, unchanged with fields present; first registration wins in both orders; the `_fields` gap answered with the fixed 500 on every shape, after the route value, 415 and 413 and before the body; 404; a carrier built by hand; the raw-slot adapter function on production `App`, moved from the spike; and DX section 4's typed header access example.
  - `tests/with_headers_api_fail` (7, `check.sh`), on production `WithHeaders`: no `from_body` (`'WithHeaders[Note]' value has no attribute 'from_body'`), a nested carrier, `WithHeaders[Int]` and `WithHeaders[Json[T]]` without `FromJson` (`'WithHeaders' parameter 'B' has 'FromBody' type ...`), the body moved out (`field 'input.body.text' destroyed out of the middle of a value`), a carrier handler on `get` and a carrier before a route value on `post` (each a candidate note naming the carrier handler's own type). Each has one error. Built against `main`'s `src`, every one fails with `package 'muntin' does not contain 'WithHeaders'` instead, so each fails for its documented reason only with the slice.
  - `adapters/flare/test_localhost_roundtrip.mojo`: `json_app()` serves the stateful carrier route `POST /signed-greet` (`WithHeaders[Json[Greeting]]`, credential in the state). Over HTTP/1.1, repeated `X-A`/`x-a` fields reach the handler in order with their casing (200), a missing credential is the handler's 401, and a missing `Content-Type` is 415; each status and body equals `App.handle` with the test's fields. The handler echoes only `X-A` fields, because Flare's client adds fields of its own.
  - Mutations (planted in scratch copies of `src/muntin`, never in the tree), each red: the fields flag missing on each of the eight body overloads; the fields not appended; the fields appended for every body route (a plain `Json[T]` route answers 415); the carrier without `_JsonBody` forwarding; the first field read at the verdict's index; the JSON steps before the route value; a body conversion failure answered 500; the rebuild failure answered 400; the rebuild moved before the route value and the JSON steps (added after a fresh-context review found that order untested); the JSON flag missing with the parity check removed, both on every body overload and on carrier routes only; the carrier conforming to `FromBody` (`carrier_has_no_from_body` and `nested_carrier` build); the body bound relaxed with the check moved into `_from_parts` (`nested_carrier`, `carrier_of_int` and `carrier_of_json_without_from_json` build). Inert: the parity check removed alone. While every JSON carrier route sets its flag, no request tells it apart, and the JSON flag missing on carrier routes is red with or without it, as M3-009 recorded for its arity check.
- Spike retired: `tests/header_access_spike.mojo`, `tests/test_spike_header_access.mojo` and the five carrier fixtures in `tests/header_access_fail` are deleted, and `check.sh` registers `tests/with_headers_api_fail`. `tests/header_access_fail` keeps the three toolchain pins.
