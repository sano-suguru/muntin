# OpenAPI and schema output decision (M3-091)

> **Current.** Not built yet: its "Next production slice" is M3-092.

Status: **decision** (M3-091, issue [#142](https://github.com/sano-suguru/muntin/issues/142)). Evidence: its pull request.

**Question and what settles it.** The types that `App.handle` reads and writes (route values, `Json[T]` bodies and results) say most of an HTTP API's shape, and an application that publishes an OpenAPI document keeps a second copy of it by hand. [M3-082](m3-082-derived-json-codecs-decision.md) made a `JsonFields` struct's JSON form a function of its fields, so its schema can be derived without drifting from what is sent. Through what Muntin-owned API does an application get an OpenAPI document of its routes; what does the document say for each slot kind, result and hand-written codec without claiming anything `App.handle` does not do (a `Json[T]` result's status is chosen at run time, an `Optional` member reads absent or `null` but is written `null`, a hand-written codec has no schema); what does it do with routes OpenAPI cannot represent (repeated path names, two path templates OpenAPI treats as one); and what does it cost an application that never asks for the document? Settled by Mojo 1.1.0 probes; a scratch copy of production passing `check.sh`, `test.sh` (the spike under AddressSanitizer too) and `check_flare.sh`, with a spike through `TestClient`; its documents checked by an OpenAPI 3.1 validator, and the JSON the spike's routes send and accept checked against their schemas; build times measured against the base; and a fresh-context review.
