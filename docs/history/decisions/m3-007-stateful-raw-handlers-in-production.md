# Stateful raw handlers in production (M3-007)

> **Current.** Now described in [state reference, "Raw handlers"](../../reference/state.md#raw-handlers), [raw reference](../../reference/raw.md#raw-handlers-and-binary-bodies) and [state reference, "Errors"](../../reference/state.md#errors).
> Changed in part since:
> - [M3-014](m3-014-registration-structure-decision.md): raw selection by the shorter parameter list and the ten-overload note budget are gone (arity overloads).
> - [M3-015 production](m3-015-registration-on-generic-arity-slots-in-production.md): `_call_state_raw` and the two stateful raw overloads became the arity adapters/overloads.
> - [M3-030](m3-030-method-not-allowed-decision.md): `PUT /keyed` (path matches, method does not) is now 405 with Allow, not 404.
> - [M3-053](m3-053-route-conflict-decision.md): "first registration wins" across raw and typed duplicates became a registration abort.
> Its pointers into documents that were split or renamed since (`docs/DX.md`, old `docs/ARCHITECTURE.md` headings) are mapped in [the list of records](../architecture-decisions.md#documents-older-records-cite).

Status: **production**, the raw member of the M3-001 family on M3-004's storage; with M3-003 and M3-006 it completes the stateful handler family. Decision: "Application state decision (M3-001)" (the *Raw* shape and *Inside the family*); raw semantics: "Raw Request handlers in production (M2-015)" and "Headers in production (M3-005)".

- `src/muntin/app.mojo`: one adapter, `_call_state_raw[S, E]`, which is `_call_raw` with `bound.state` passed first by borrow, and two overloads, `App.get` and `App.post`, each `[S, E, //, path]` taking `(handler: def(State[S], var Request) thin raises E -> Response, state: State[S])`. Each is placed last in its method's group and repeats the raw twin's route checks and messages. A registration stores the handler and one copy of the handle as M3-003's `_Bound[H, S]` in `_Erased`, with `raw=True`; requests borrow it. `_call_raw`'s request rebuild moved into `_raw_request(args) raises -> Request`, which both raw adapters call; a rebuild failure is still the fixed 500, and `tests/test_raw.mojo` and `tests/test_headers.mojo` pass unchanged.
- Selection: on `post` a stateful raw handler also satisfies the stateful `ToResponse` body overload (`B = Request`, `R = Response`). The raw overload's list `[S, E, path]` (3) is shorter than `[S, B, E, R, path]` (5), so M2-014's rule selects it; the `String` body overload is not viable for a `Response` result. Mutation: two defaulted parameters on the stateful raw `post` make the lists equal, and every such call becomes `ambiguous call to 'post'`. On `get` no other stateful overload's handler type has a `Request` parameter. The argument count separates stateless and stateful raw routes, as for the typed shapes.
- The stateful body overloads' `Request` guard names the stateful raw shape: `Request is the whole request, not a body; a stateful raw handler takes State first, then only the Request, and returns Response`. It used the stateless text (`a raw handler takes only the Request and returns Response`), which pointed a stateful handler at a shape without its state. The stateless overloads keep their text. It changes only messages: selection is unchanged, and no existing fixture expected the old text from a stateful overload (the retired `state_post_fail/raw_stateful_post.mojo` was the only one).
- Unchanged: `_Erased`, `_Call`, `_Route`, `_handler_storage.mojo` (`_Shared`), `check_unsafe.sh` and the unsafe surface, `State` and its marker, `_Bound`, the typed and stateful typed overloads and adapters, `App.handle`, `http.mojo`, `body.mojo`, `testing.mojo`, `adapters/flare/muntin_flare.mojo`. `App` stays non-generic.
- Note budget (revisit condition): `get` and `post` now have ten overloads each, and Mojo 1.1.0 shows at most ten notes. A failing one-argument call shows ten candidate notes and no detail note. One more overload on either method (for example raw route values or raw `String`/`ToResponse` results, which SPEC lists as candidates) would drop candidate notes themselves, so DX's "one note per candidate" would stop holding. Such a slice must measure its diagnostics against this budget.
- Behavior: the raw twin's, with the state first. The handler receives the whole `Request`, moved in as raw handlers receive it: method, path, the query undecoded, the body (empty included) and the header fields in order with their casing and repeats. No typed extraction runs (no query gathering, `_parse_int` or `from_body`), so Muntin answers no 400 after the match. The `Response` is the answer, unconverted; its status, body and fields survive, and the Flare adapter applies its outbound rule to the fields. A raise is `ToErrorResponse` or the fixed 500; 404 without a match; the first registration wins across stateless raw, stateful raw and typed routes, and a typed route's 400 does not fall through. Route literals stay static.
- Lifetime: each registration raises the handle's count by one; requests on both methods leave it unchanged, read inside handlers and across successful, 401, 500 and 404 requests; dropping the `App` releases the routes' handles; the value is dropped once across two `App` moves.
- Diagnostics: of the 204 existing must-fail fixtures (all directories, built against production; `raw_stateful_post` retired), 171 are identical. In the 33 that change, every error line and caret is identical; only notes change:

  - 14 failing two-argument calls gain the stateful raw candidate's note (`state_get_fail`: `mismatched_state_type`, `owned_state_parameter`, `plain_value_as_state`, `state_for_stateless_handler`, `state_last`; `state_post_fail`: `mismatched_state_type`, `mut_state_parameter`, `owned_state_parameter`, `plain_value_as_state`, `plain_value_parameter`, `state_after_body`, `state_after_route_value`, `state_for_stateless_handler`, `state_without_body`);
