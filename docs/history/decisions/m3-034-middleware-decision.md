# Middleware decision (M3-034)

> **Current.** Now described in [middleware reference](../../reference/middleware.md), [ARCHITECTURE, "Request handling"](../../ARCHITECTURE.md#request-handling) and [ARCHITECTURE, "Storage and ownership"](../../ARCHITECTURE.md#storage-and-ownership).
> Changed in part since:
> - [M3-063](m3-063-request-context-decision.md): the owning App.handle (built as M3-064) hands the request to the first middleware without the copy M3-034 named as its cost; only a lent request is copied.
> Its pointers into documents that were split or renamed since (`docs/DX.md`, old `docs/ARCHITECTURE.md` headings) are mapped in [the list of records](../architecture-decisions.md#documents-older-records-cite).

Status: **decision** (M3-034, PR #72; `src/muntin`, `adapters/` and `compat/` are unchanged in it). It decides whether and how application code wraps request handling in Muntin-owned middleware. The question and what settles it were committed before any measurement (`docs/DEVELOPMENT.md` section 2).

**Why now.** Middleware is a `docs/SPEC.md` candidate that earlier records postponed for ordering, not on a revisit condition: `App.handle` is already the one seam and no handler shape depends on what wraps it (M3-018, M3-020), and it needs a hook stored with the `App`, which on Mojo 1.1.0 cannot be a capture or a module-level variable (M3-022, M3-024). Serving shipped in M3-033, so a program can now be wrapped end to end; the author chose middleware next.

**Question.** What is the smallest Muntin-owned middleware contract, registered on `App`, with which application code can (1) inspect a request, (2) answer it itself without calling the rest (short-circuit), (3) call the rest of the chain, and (4) inspect or modify the response it returns, with DX section 7's `app.use(Tracing())` as the reference shape? In particular:
- the contract's spelling: a trait that application structs implement, a function type, or a pair of hooks around the rest;
- how a middleware value is stored in the non-generic `App`, and whether that widens the unsafe operations confined to `_handler_storage.mojo` (M2-004, M3-004);
- what "the rest of the chain" is as a value: its type, whether middleware can keep it past the call or call it more than once;
- which requests middleware sees (every request `App.handle` receives, including 404, 405 and the pre-handler 400s, or only matched routes), in which order several run, and whether `use` after a route registration differs from before;
- how a raise inside middleware is answered;
- how it composes with `HEAD` (the backend drops the content after `App.handle`, M3-027), `TestClient` and `Server` (both call `App.handle`);
- what it costs an `App` that registers none;
- whether request-scoped typed context (DX section 7's fifth property: middleware attaching a typed value a handler reads) is decided here or deferred, given M3-001's rule that a second injected kind needs its own decision because it would double the overloads.

**What settles it:**
- the current dispatch path (`App.handle`) and storage (`_Erased`, `_Shared`) traced in code, with M3-001's injection rule and M3-004's storage guarantee;
- per candidate, a spike built with Mojo 1.1.0 in the default environment (library side under `tests/`, production untouched): a user program built with `--Werror` that registers middleware doing each of (1) to (4); answers through `TestClient` for a fixed request set (a matched route, 404, 405 with `Allow`, a 400 from a bad route value, `HEAD`, a handler raise), each with and without middleware, compared with what the candidate's rule says; two middleware in order; a raise in middleware; the diagnostic for a value that is not middleware;
- whether "the rest" can outlive the call, by a must-not-build probe when the candidate passes such a value;
- for the selected candidate, a scratch copy of the repository with it applied to production (not retained): `src/muntin` precompiles, `check_boundaries.sh` and `check_unsafe.sh` pass (or the record names the one rule that widens and why), and `./scripts/check.sh`, `./scripts/test.sh` and `./scripts/check_flare.sh` exit 0 with every existing suite count and fixture expected text unchanged;
- what the selected candidate cannot express on Mojo 1.1.0, each with a minimal reproduction, and the closest type-safe alternative (AGENTS.md).

**The paths today.** `App.handle(self, request: Request) -> Response` matches routes, decodes and converts, and answers 400, 404, 405, a handler's answer or the fixed 500 (`_internal_error()`, no error text). `TestClient` and both Flare handlers (`MuntinHandler`, `Server`'s `_BorrowedHandler`) call it and nothing else; `HEAD`'s content is dropped by the adapter afterwards (M3-027). A registration stores a handler in `_Erased`, whose stored call is `def(F, List[String]) raises -> Response`; `_Shared` holds `State` values. `_handler_storage.mojo` is the only module with unsafe operations, imports only the standard library and `.http`, and names no request or body data (`check_unsafe.sh`, M2-006). On Mojo 1.1.0 handlers cannot capture and module-level variables do not compile (M3-001).

**Measured premises.** Mojo 1.1.0, default environment. `tests/middleware_spike.mojo` puts one chain in front of an unchanged production `App` (`MwApp`), with every candidate's registration on it, and `tests/test_spike_middleware.mojo` (11 tests) runs the candidates on one request set: `GET /hello`, `GET /users/7`, `GET /users/abc` (400), `GET /missing` (404), `POST /hello` (405, `Allow: GET, HEAD`), `HEAD /hello`, a handler raise (500) and a `POST` body. One deviation from "What settles it": the spike sends requests through `MwApp.handle`, not `TestClient`, because `TestClient` takes a production `App`, which has no chain; the production scratch copy below sends a subset through `TestClient`, and the next slice's tests go through it.
- **The rest of the chain as a value.** A struct field cannot hold `AnyOrigin` (`struct fields cannot expose AnyOrigin in their type`, scratch probe, not retained). `Next[o]` holds an immutable `Pointer` to the chain owner with the origin `o` of the borrow that made it, and the next index; its origin, not its traits, keeps it from outliving that borrow. It is `Movable`, not `Copyable`: `next.copy()` is `value has no attribute 'copy'` (`tests/middleware_fail/next_not_copyable.mojo`), and passing it where `Copyable` is required is `does not conform to trait 'Copyable'` (`next_not_copyable_trait.mojo`). Its one call, `next^.run(request^)`, takes `deinit self`, so the call consumes it: calling it twice, or inside a loop, is `use of uninitialized value 'next'` (`next_called_twice.mojo`, `next_called_in_loop.mojo`), and it has no plain call (`next(request^)`: `does not implement the '__call__' method`, `next_plain_call.mojo`). A function type generic over `o` (`def[o: Origin[mut=False]](var Request, var Next[o]) raises thin -> Response`) is storable in a `List`, and an application function written with `var next: Next` converts to it; one that borrows the request or does not raise converts too (review probe). This is the smallest form measured here, not a proof that no other form exists.
- **The once rule, three ways.** Unguarded (a borrowed `Next` with a plain call, first measured): a middleware that calls `next` twice runs the rest twice, a route's handler included, so a `POST` with side effects would run twice. Guarded at run time (a second origin and a flag in the caller's frame, measured in `a8de28c`): the second call runs nothing and is the fixed 500, but only when it happens, and the flag is a field a middleware can reset by name (review probe: writing `next._called[] = False` between two calls reaches the handler twice). Guarded by type (above): a second direct use of `next` does not compile; one origin parameter, no flag. Moving `next` into a container does not escape the rule but defers it to run time: `var o = Optional(next^)` and two `o.take().run(...)` build, run the rest once, and the second `take()` aborts the process (review probe; an abort, not a raise, so no 500 answers it). Code that names `_` members can still reach the chain owner through `next._app[]`, the same boundary as M2-004's and M3-004's ("ordinary paths"); and the spike's `Next` initializer is public, so code holding the chain owner can build a `Next` past the middleware (review probe), which production must not allow (slice below). Every guarantee below is for code that names no `_` members.
- **Without middleware, or with a pass-through, every candidate answers the request set exactly as the `App`** (status, body and every field, `Allow` included).
- **What each candidate was shown to do.** F: (1) a middleware sees the method of every request `App.handle` receives, 404, 405, the pre-handler 400 and the handler's 500 included, and `HEAD` arrives as `HEAD`; (2) it answers without calling `next`, and the route's handler is not called (a `State` count stays 0); (3) and (4) it rewrites the request's path before `next` and adds fields to the response after it; order; a raise; compile-time parameters. A: (1) and (2) by path (`Gate`), (4) a response field (`Tag`), a runtime value, dropped exactly once after two moves of the chain owner. A′: a pass-through and (4) a response field. H: (1) the method of every request (`after`), (2) a `before` answer with the handler not called. Request rewriting through A or A′ and an A′ short-circuit were not measured; they call the same `Next`. A′ builds its value on every call by construction (`materialize`); its allocations were not measured.
- **Order:** registration order, outermost first: two middleware writing a request field and a response field give `a,b` on the way in and `b,a` on the way out. Middleware wraps the whole `App`, so registering it after a route changes nothing.
- **A raise in middleware** is the fixed 500, made at that middleware's call (`_run` catches around each link): the middleware outside it receives the 500 from its `next` as an ordinary response and runs the rest of its code (`test_a_raise_is_answered_at_the_failing_middleware`; a raise before `next` leaves the handler uncalled, after `next` it was called once).
- **Configuration:** F takes compile-time parameters (`use(tagged["v1"])`); a capturing closure does not convert (`function_captures.mojo`). A takes a runtime value (`use(Tag("run" + suffix))`). A′ takes only a compile-time value (`use[Tag("static")]()`; a runtime one is `cannot use a dynamic value in call argument`).
- **Diagnostics** (with every registration of the spike as a candidate; production, with one `use`, will word them differently): a value that is not middleware is `does not conform to trait 'Middleware'` (A) and `cannot be converted from 'IntLiteral[42]' to 'MiddlewareFn'` (F, `function_plain_value.mojo`), and a function without `next` is `cannot be converted from 'def no_next(...)' to 'MiddlewareFn'` (F), followed by a note spelling the function type out.
- **Storage:** F and A′ store thin function values, no erasure. A stores values of application types behind `_ErasedMw`, a box modeled on `_Erased` whose stored invoke function is generic over `next`'s origin; it names `Request` and `Next`.
- **Library only:** `tests/middleware_lib_only/driver.mojo` registers each candidate with types the library has never seen.
- **Mutations** (planted in the spike, reverted; 7), each red: `next` skipping a link (3 tests), the chain run in reverse (2), a `before` hook's answer ignored, the erased box never dropping its value, the raise caught only around the whole chain (the outer middleware's field missing), `run` taking `self` instead of `deinit self` (`next_called_twice.mojo` and `next_called_in_loop.mojo` then build, which `check.sh` reports), and `Next` declared `Copyable` (`next_not_copyable.mojo` and `next_not_copyable_trait.mojo` then build).
- **Production, scratch copy (not retained).** F applied to `src/muntin/app.mojo` (`Next`, the function type, `App.use`, `App.handle` running the chain, its old body moved to `_dispatch` and called directly when no middleware is registered) and `Next` exported; a scratch test through `TestClient`. The pull request's "Verification" gives the three scripts on it.

**Selected: F, middleware functions, with a `Next` the middleware can call once.**

```mojo
from muntin import App, Next, Request, Response


def tracing(var request: Request, var next: Next) raises -> Response:
    var response = next^.run(request^)
    response.headers.add("X-Trace", "1")
    return response^


def main() raises:
    var app = App()
    app.use(tracing)
    app.get["/users/{id}"](get_user)
```

- **Contract.** `app.use(f)` takes a thin function `def(var Request, var Next) raises -> Response`; a function that borrows the request or does not raise also converts. It may change the request, answer without running the rest, or run the rest once with `next^.run(request^)` and change the response that returns. Configuration is compile-time: the function's own parameters (`app.use(cors["https://app.example"])`). No value is stored with it.
- **`Next`.** Public and Muntin-owned. `run` consumes it, so the rest runs at most once per middleware call: a second direct use of `next` does not compile, and a `Next` moved into a container and taken twice aborts the process at the second take instead of running the rest again. It is not `Copyable`, its origin keeps it inside the call that received it, and no public spelling constructs one (code that names `_` members can, as above). The function type gets a public name (`Middleware`), so users can name it and diagnostics show that name.
- **Scope.** Every request `App.handle` receives, in registration order, outermost first, whenever `use` is called. That includes 404, 405 and the pre-handler 400s: a middleware that answers 401 before running the rest answers 401 for a path no route matches too, which is the order the application chose. Requests a backend refuses before calling `App.handle` (Flare's own 400s and its 413 over `max_body_size`) never reach middleware; that is a description of where `App.handle` sits, not a tested rule.
- **Muntin's own answers.** Middleware that does not touch a response passes it through unchanged. Middleware may replace or change any response, Muntin's included: that is the application's way to answer a 404 or a 405 itself, which settles M3-030's condition "applications need their own answer for a 405 or a 404 (a fallback or middleware)": Muntin's fixed answers stay the default, and keeping `Allow` on a 405 the application builds or changes is the application's responsibility.
- **Errors.** A raise out of a middleware is the fixed 500 at that middleware's call; no error text reaches the client; the middleware outside it continues with that 500. Middleware has no error type of its own.
- **`HEAD`, `TestClient`, `Server`.** Unchanged: they call `App.handle`. A middleware sees `HEAD` as `HEAD`; the backend drops the content of whatever response comes out.
- **Cost.** An `App` with no middleware dispatches as before, plus a length check (by construction; not measured). With middleware, `handle` copies the borrowed request once (method, path, query, header fields and body), because `App.handle` borrows the request and middleware takes it by value. Over Flare with its default 10 MiB `max_body_size`, the body alone can be up to 10 MiB of that copy; `TestClient` and other in-memory callers have no such limit. Each layer is one call and one `Next`. No timing was measured.
- **Not in this decision.** Runtime-configured middleware (A), request-scoped typed context, per-route or per-group middleware, middleware error types. A middleware can allow or deny a request, but it cannot hand an authenticated identity to a handler: request header fields are client input (a client can send the same name first), so writing one for a handler to trust is not a substitute, and an application must not use it as one.

**Candidates.**

| Candidate | Verdict |
|---|---|
| 0: no middleware | rejected: no way to wrap requests; a raw handler cannot reach the `App` (no captures) |
| F: thin functions, `app.use(f)`, `Next` consumed by its call | **chosen**: (1) to (4) on every request `App.handle` receives; the rest runs at most once, checked at compile time; a `List` of function values on `App` and no new type-erased storage, no unsafe operation, no change to `_handler_storage.mojo` or `check_unsafe.sh`; configuration compile-time only; the call is spelled `next^.run(request^)` |
| F with a borrowed `Next` and a run-time guard | rejected: a second call is a 500 when it happens, not a compile error; one more origin parameter and a flag a middleware can reset by name |
| F with a borrowed, unguarded `Next` | rejected: a second call runs the rest, a route's handler included, twice |
| A: values of application structs conforming to `Middleware`, `app.use(Tracing())`, type-erased | deferred (revisit below): DX section 7's spelling and runtime configuration, at the cost of a second erased box. Its stored call names `Request` and `Next`, so the storage module would name request data (M2-006) and import beyond `.http`, two `check_unsafe.sh` rules widened, and one more invariant the compiler does not check (each box restored only as the type it was made with) to maintain. Not a hole on ordinary paths (unlike M3-001's A2) |
| F and A together | rejected now: two spellings of one feature, and A's cost |
| A′: compile-time struct values, `app.use[Tracing()]()` | rejected: A's spelling without A's runtime values; the value is built on every call; an unusual registration form |
| H: `app.before(h)` and `app.after(h)` hooks | rejected: nothing passes between a request's `before` and `after` (timing a request needs a value from one to the other), and two registration names for one concept |

**Costs.** Runtime configuration (a secret or an allowed origin read at start-up) has no supported path; the closest are compile-time parameters, or reading the environment inside the middleware on every call, which is not a recommendation. Authentication middleware can gate requests but cannot hand a typed identity to handlers, so it is not a complete authentication feature. The once rule costs the spelling `next^.run(request^)` (`next^(request^)` parses as an XOR).

**Revisit when:**
- an application example needs a start-up value, secret or state in middleware and F with existing features cannot express it properly: decide A (or `app.use(f, state)` over `State`). Measure then: F and A registered in one chain in registration order, the erased box's safety under the storage guarantee (M3-004), and whether F's spelling stays unchanged. The aim is to keep F's API; this record does not claim that adding A leaves the internal storage unchanged;
- request-scoped typed context is proposed (an identity a handler receives): its own decision, because a second injected kind doubles the overloads (M3-001);
- a fixture in `tests/middleware_fail` builds or loses its text (`run` stops consuming `Next`, `Next` gains a plain call or becomes `Copyable`, a capturing closure converts to a middleware function, a value that is not middleware registers): re-measure the once rule;
- Mojo lets a consuming call be spelled without `^` at the call site: revisit the spelling;
- per-route middleware or middleware error types are needed: their own decisions;
- streaming or a non-`Copyable` request body is designed, or the per-request copy of the request is measured as a cost: revisit whether middleware takes the request by value.

**Next production slice (M3-035): middleware functions.**
- Code: `src/muntin/app.mojo` only, plus `Next` and `Middleware` exported from `muntin`.
